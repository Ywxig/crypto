## Использование

Для запуска шифрования/дешифрования передайте нужный флаг и сообщение в качестве аргументов:

* `-Ecsr` - Зашифровать шифром Цезаря (сдвиг)
* `-Dcsr` - Расшифровать шифром Цезаря (сдвиг)
* `-Ecsk` - Зашифровать шифром Цезаря с ключевым словом
* `-Dcsk` - Расшифровать шифром Цезаря с ключевым словом
* `-Evgn` - Зашифровать шифром Виженера
* `-Dvgn` - Расшифровать шифром Виженера
* `-I`    - Запустить интерактивный режим
* `-F`    - Прочитать файл
* `-v`    - Показать версию программы

### Чтение файлов

Вы можете использовать флаг `-F` для быстрого вывода содержимого текстовых файлов прямо в терминал:

```bash
./dist/main -F <путь_к_файлу>
```

### Красивый вывод и раскраска текста

В движке реализован собственный простой синтаксический парсер для раскрашивания текста в консоли (через ANSI-последовательности). Парсер находит в строке специальные цветовые теги-токены и заменяет их на соответствующие коды.

#### Доступные цветовые теги
* `<red>` — Красный
* `<green>` — Зелёный
* `<yellow>` — Жёлтый
* `<blue>` — Синий
* `<magenta>` — Пурпурный
* `<cyan>` — Голубой
* `<white>` — Белый
* `<reset>` — Сброс цвета к системному значению по умолчанию

#### Особенности работы
1. **Автоматический сброс (`<reset>`)**: Парсер гарантирует безопасность отображения. Даже если вы забыли поставить тег `<reset>` в конце строки, функция **автоматически принудительно добавит его в самый конец**, чтобы цвета вашего терминала не «сломались» после завершения работы программы.
2. **Кросс-языковая интеграция**:
   * Для кода на **C++** используется функция `echo(const std::string& message)`.
   * Для алгоритмов на чистом **C** доступен C-совместимый мост в виде функции `c_print_colored(const char* message)`.

#### Пример использования в коде
```cpp
// C++ пример:
std::cout << echo("Это <red> красный <reset> текст, а это <yellow> жёлтый");
```
> [!NOTE]
> Для форматированного вывода доступна функция `c_print_format(const char* format, ...)`. это парсер который сам парсит строку и заменяет цвета на ANSI-коды
```c
// C пример:
c_print_format("Это <green> зелёный <reset> текст");
```

## Алгоритмы

### 1. Шифр Цезаря (Caesar Cipher)
* **Как работает:** Это классический шифр подстановки, в котором каждая буква в сообщении сдвигается на фиксированное число позиций (ключ) по алфавиту. Например, при ключе `3` буква **A** заменяется на **D**, **B** на **E** и так далее. Если сдвиг выходит за пределы алфавита (например, буква **Z**), отсчет начинается сначала (циклически).
* **Особенности:** Очень простой, но крайне уязвимый к взлому шифр, так как возможных вариантов сдвига всего 26.

> [!NOTE]
> Для шифрования Цезаря (сдвиг)
```bash
./dist/main -Ecsr <сообщение>
```
#### Математическая логика

Каждая буква латинского алфавита кодируется числом от `0` до `25` (`A=0, B=1, ..., Z=25`). Это множество из 26 чисел с операцией сложения образует **кольцо вычетов по модулю 26** (`ℤ₂₆`) — конечную циклическую структуру, в которой после `25` снова наступает `0`. Именно эта операция `mod 26` и «заворачивает» индекс обратно в диапазон `[0, 25]`, когда сдвиг выходит за букву `Z` — отсюда циклический эффект шифра.

* Для шифрования Цезаря также есть реализация через математические операции. Это даёт прирост к скорости шифрования, но не ощутимый. Однако это здорово сокращает код, используя только математические формулы:

$$E(m_i) = (m_i + k)\pmod{26}$$

$$D(m_i) = (m_i - k)\pmod{26}$$

где `m_i` — числовой код буквы сообщения, `k` — ключ (сдвиг). Шифрование и дешифрование — взаимно обратные операции: сложение по модулю компенсируется вычитанием того же числа по тому же модулю. Так как `k` принимает только 26 различных значений, всё пространство ключей исчерпывается 26 вариантами, что и делает шифр тривиальным для перебора.

> [!IMPORTANT]
> Для дешифрования Цезаря (сдвиг) с математическими операциями
```bash
./dist/main -Ecsrm <сообщение>
```

> [!NOTE]
> Для дешифрования Цезаря (сдвиг)
```bash
./dist/main -Dcsr <сообщение>
```

> [!IMPORTANT]
> Для дешифрования Цезаря (сдвиг) с математическими операциями
```bash
./dist/main -Dcsrm <сообщение>
```

### 2. Шифр Цезаря с ключевым словом (Caesar Keyword Cipher)
* **Как работает:** Модификация классического Цезаря. Вместо числового сдвига используется секретное **ключевое слово** (например, `MEETING`). Сначала в алфавит записываются уникальные буквы этого слова, а затем все остальные буквы английского алфавита, которых не было в слове. Получается новый перемешанный алфавит подстановки, по которому и шифруется сообщение.
* **Особенности:** Гораздо надежнее классического Цезаря, так как количество возможных комбинаций алфавита намного больше.

#### Математическая логика

В отличие от Цезаря, здесь нет единой арифметической формулы вида `+k mod 26` — вместо сложения строится **перестановка (биекция)** алфавита `π: A → A'`:

1. Уникальные буквы ключевого слова выписываются по порядку появления (повторы отбрасываются).
2. К ним дописываются оставшиеся буквы алфавита по возрастанию, которых не было в ключе.
3. Получившаяся последовательность `A'` — это переставленный алфавит, где символу на позиции `i` исходного алфавита соответствует символ на позиции `i` нового.

Шифрование и дешифрование — прямое и обратное применение этой перестановки:

$$E(m_i) = \pi(m_i), \qquad D(c_i) = \pi^{-1}(c_i)$$

Поскольку `π` — биекция (каждому элементу соответствует ровно один образ и есть однозначная обратная функция `π⁻¹`), дешифровка всегда корректно восстанавливает исходную букву. Общее число различных перестановок алфавита из 26 букв равно `26! ≈ 4·10²⁶`, что экспоненциально больше 26 вариантов ключа у классического Цезаря — отсюда и рост стойкости к перебору.

> [!NOTE]
> Для шифрования Цезаря с ключевым словом 
```bash
./dist/main -Ecsk <сообщение>
```

> [!NOTE]
> Для дешифрования Цезаря с ключевым словом 
```bash
./dist/main -Dcsk <сообщение>
```

### 3. Шифр Виженера (Vigenère Cipher)
* **Как работает:** Это метод шифрования буквенного текста с использованием ряда шифров Цезаря, основанных на ключевом слове. Каждая буква ключа определяет размер сдвига для соответствующей буквы сообщения. Буквы ключа применяются циклически: когда ключ заканчивается, он начинается заново с первой буквы. 
* **Особенности:** Благодаря использованию повторяющегося ключа, одна и та же буква в исходном сообщении может шифроваться по-разному в зависимости от её позиции, что значительно защищает текст от простого частотного анализа.

#### Математическая логика

По сути это тот же Цезарь, но ключ — не одно число, а **последовательность чисел** `k₀, k₁, ..., k_{ℓ-1}` (числовые коды букв ключевого слова длиной `ℓ`), которая циклически повторяется на всю длину сообщения:

$$E(m_i) = \left(m_i + k_{\,i \bmod \ell}\right) \pmod{26}$$

$$D(c_i) = \left(c_i - k_{\,i \bmod \ell}\right) \pmod{26}$$

Индекс `i mod ℓ` — это то, что заставляет короткий ключ «зацикливаться» на длинном сообщении: как только буквы ключа заканчиваются, отсчёт снова начинается с `k₀`. Фактически на каждой позиции применяется свой сдвиг Цезаря, поэтому одна и та же буква сообщения на разных позициях почти всегда превращается в разные буквы шифротекста — в этом и заключается **полиалфавитность**, ломающая прямой частотный анализ. Пространство ключей для ключевого слова длины `ℓ` составляет `26^ℓ` вариантов.

> [!NOTE]
> Для шифрования Виженера 
```bash

```

> [!NOTE]
> Для дешифрования Виженера 
```bash
./dist/main -Dvgn <сообщение>
```

### 4. Алгоритм Диффи-Хеллмана (Diffie-Hellman)
* **Как работает:** Протокол, с помощью которого две стороны (A и B) договариваются об общем секретном числе, даже если весь обмен происходит по открытому каналу. Стороны выбирают публичные `p` (простое число) и `g` (примитивный элемент по модулю `p`), после чего каждый выбирает свой секрет (`a` у A, `b` у B) и вычисляет открытый ключ: `A = g^a mod p`, `B = g^b mod p`. Обменявшись открытыми ключами, каждая сторона вычисляет общий секрет: `K_A = B^a mod p`, `K_B = A^b mod p`. Благодаря свойствам модульной арифметики оба выражения сводятся к `g^(a*b) mod p`, поэтому `K_A == K_B`, хотя `a` и `b` никогда не передавались напрямую.
* **Особенности:** В отличие от шифров выше, Диффи-Хеллман — не способ зашифровать сообщение, а способ безопасно согласовать общий ключ по открытому каналу. Классическая версия не защищена от атаки "человек посередине" (man-in-the-middle), так как не аутентифицирует стороны.

> [!NOTE]
> Быстрое возведение в степень по модулю (`mod_exp`) реализовано через бинарное разложение показателя степени — сложность `O(log exp)` вместо `O(exp)`.

> [!NOTE]
> Пример из задания: `p = 11`, `g = 2`, `a = 5`, `b = 13` → `A = 10`, `B = 8`, `K_A = K_B = 10`.

#### Математическая логика возведения в степень по модулю

Вычислить `g^a mod p` напрямую невозможно для больших `a` — число `g^a` растёт экспоненциально ещё до применения `mod`. Поэтому показатель `a` раскладывается в двоичном виде:

$$a = \sum_i c_i \cdot 2^i, \quad c_i \in \{0, 1\}$$

и степень собирается из уже посчитанных квадратов:

$$g^a = \prod_{i:\ c_i = 1} g^{2^i}$$

Отсюда алгоритм «возведение в квадрат и умножение» (`mod_exp`):

```
result = 1
base = g mod p
while a > 0:
    if a is odd:
        result = (result * base) mod p
    base = (base * base) mod p
    a = a >> 1
```

На каждой итерации разбирается один бит показателя `a`, значит требуется всего `O(log a)` умножений вместо `O(a)` — именно это и даёт прирост скорости, о котором сказано выше.

#### Почему `K_A == K_B`

Каждая сторона возводит открытый ключ другой стороны в степень своего секрета:

$$K_A = B^a \bmod p = (g^b \bmod p)^a \bmod p = g^{ba} \bmod p$$

$$K_B = A^b \bmod p = (g^a \bmod p)^b \bmod p = g^{ab} \bmod p$$

Умножение показателей степени коммутативно (`a·b = b·a`), поэтому оба выражения сводятся к одному и тому же числу `g^{ab} mod p`. При этом ни `a`, ни `b` по отдельности никогда не передавались по каналу — видны только `p`, `g`, `A` и `B`.

#### На чём держится безопасность

Обратная операция — восстановить секрет `a` по известным `g`, `p` и `A = g^a mod p` — это задача **дискретного логарифма**. Для больших простых `p` эффективного (полиномиального) алгоритма её решения не существует: доступны только методы с экспоненциальной или субэкспоненциальной сложностью (полный перебор, «шаг младенца — шаг великана», ро-алгоритм Полларда и т. д.). Поэтому наблюдатель, видящий только `p`, `g`, `A`, `B`, не может практически вычислить общий секрет `K`.
